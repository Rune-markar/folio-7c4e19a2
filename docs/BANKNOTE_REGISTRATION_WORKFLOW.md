# 保有資料写真から紙幣を登録する手順

保有資料の写真フォルダを受け取ったときは、写真を「所蔵の存在と型式を照合する資料」として扱います。写真そのものを公開用の紙幣画像へ転用しません。フォルダURL、シリアル番号、収納場所など、所蔵者を特定し得る情報も公開データへ残しません。

## 1. 写真を棚卸しする

1. フォルダ内の全ファイル名を記録し、各写真を拡大して紙幣ごとの表裏、国・発行体、額面、通貨、券面日付、シリーズ、署名、記号・番号、特徴的な文言を読む。
2. 同じ紙幣が複数写真へ写っている場合は一件へまとめる。表裏の対応に確信が持てないものは登録せず、「未確定」として依頼者へ示す。
3. `data/collection.json` の国、額面、通貨、年代、図柄と照合する。既存券と一致すれば重複登録せず、誤った型式・画像・年・カタログ番号だけを修正する。

## 2. 型式を確定する

1. 中央銀行、発行機関、法令データベースなどの一次情報を優先する。
2. Numista、PMG等の専門カタログを併用し、Pick番号、発行年範囲、署名、シリーズ番号、表記差を突き合わせる。販売ページだけで型式を決めない。
3. 写真から読めた事実と、外部資料から補った事実を区別する。型式、表裏、発行年のいずれかが確定できない場合は推測で登録しない。

## 3. 公開用画像を選ぶ

公開用画像は保有資料写真とは別に探し、次をすべて確認します。

- 発行体、額面、通貨、年、シリーズ、版・型が登録対象と一致する。
- 表面と裏面が同じ型式の組である。
- 紙幣全体と主要文字が読み取れ、過度な傾き、ぼけ、指、背景物、販売店名、ロゴ、透かし文字、`SPECIMEN` 表示がない。
- 出典ページ、画像URL、確認日、表示されたライセンスまたは利用条件を `media/SOURCE.md` に残す。
- 非営利限定画像は非営利公開に限る。個別ライセンスまたは発行国の複製条件が確認できない画像は、その旨を記録して公開・再配布前に再確認する。

保存名は原則 `media/<国コード>-<額面>-<基準年>-front.jpg` と `...-back.jpg` とし、長辺は表示に十分な範囲（現在は最大1200px）へ整えます。

## 4. データを登録する

`data/collection.json` へ一意な `id` を付け、少なくとも国、地域、通貨、額面、発行年、シリーズ、タイトル、物語、モチーフ、所蔵数、状態、カタログ番号、画像パスを登録します。

- `story` は「肖像・人物」「発行背景」「当時の社会情勢」「特殊な点」「採用モチーフ」の順で記述する。
- 現物状態と評価額は写真だけで断定せず、未鑑定なら `condition: "未評価"`、`estimatedValue: 0` とする。
- 新規写真照合分には `写真照合登録` タグを付け、`sourceSnapshot.photoRegistrationCount` を増やす。
- 記念紙幣は `issueType` に「記念紙幣」と記念加刷の別を記録し、タイトル・シリーズ・解説・タグでも通常券との違いと記念対象を明示する。基券へ加刷した券は基券の年・Pick番号と記念加刷年を混同しない。
- 既存登録の訂正は新規件数へ含めず、誤画像の参照と不要ファイルを残さない。

## 5. 検証して報告する

1. 新規紙幣ごとに年代、当時の国家・体制、通貨期、地図境界を確認し、`app.js` の `historicalAtlas` へ登録する。同一地域の前後期と比較すべき場合は [歴史地図の紙幣・国家系譜](HISTORICAL_ATLAS_LINEAGES.md) に従って系譜も登録する。
2. JSONが読み込めること、IDが重複しないこと、全画像パスが存在すること、表裏画像が同一でないことを機械確認する。
3. 新規・修正画像を目視し、向き、表裏、欠け、ウォーターマーク、型式一致を確認する。
4. 静的サイトを実際に配信し、その回の新規・修正対象がすべて検索・表示でき、歴史地図の年代、地域、国家・体制、系譜から到達できることを確認する。
5. 依頼者へ、新規、既存一致、修正、未確定を分けて報告する。未確定が0件でも明記する。
